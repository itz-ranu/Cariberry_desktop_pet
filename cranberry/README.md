# 🐾 Cranberry — "Hey Cranberry"

Cranberry is Cariberry's brain: the voice + text assistant behind the
**floating chat drawer** in `Cariberry.app` (open it with the 💬 button in the
control panel). Say **"Hey Cranberry"** or type in the drawer, and ask it to open
or close apps, chain tasks ("open Notion and start my study playlist"), start a
focus timer, help with homework, rewrite an email, or just chat. When it opens an
app, it visibly moves the real cursor — styled as a paw — to the app's Dock icon.

There is no window of its own any more (the old Tkinter chat is gone): every pixel
you see is native SwiftUI inside Cariberry, and this process is just the brain.

It runs as its own local Python process, separate from `Cariberry.app`. The
two only ever talk over a loopback socket (127.0.0.1:8765) — see
`Sources/DesktopPup/CranberryBridge.swift` for the Swift side.

## What's actually "from scratch" here, and what isn't

By default everything genuinely trainable is trained from scratch on this
machine, with **zero pretrained checkpoints and zero cloud calls**. (You can
*optionally* connect a chat brain: see "Chat brains" below. Nothing leaves your Mac
unless you do.)

- **Wake-word detector** (`audio/`) — a small CNN over your own recorded
  "Hey Cranberry" clips. It doesn't exist until you record samples and train
  it.
- **Brain** (`brain/`) — a from-scratch intent classifier (which command is
  this?) and a small transformer (~800K params) for persona small talk.
  Trained on a synthetic corpus generated by `brain/dataset_gen.py`.

One piece is deliberately **not** from scratch: turning an arbitrary spoken
sentence into text (open-vocabulary speech-to-text) is not something a
from-scratch model can realistically do here — Whisper alone took 680,000
hours of audio to train. For that one piece, Cranberry asks Cariberry.app to
use macOS's own on-device `Speech` framework (see `CranberryBridge.swift`).
That's OS-provided, runs fully offline, and isn't a third-party AI API —
closer to using the camera than to calling Gemini/OpenAI — but it's worth
being upfront that it isn't something we trained.

## Honest limits of the from-scratch brain

This is a few-hundred-thousand-parameter model trained on a few hundred
templated sentences in under a minute on a laptop. It is **not** a
general-knowledge chatbot. It's good at:
- recognizing "open/close `<app>`" in many phrasings, reliably (this part is
  never left to free-form generation — see `brain/infer.py`)
- warm, on-brand small talk for greetings/thanks/"how are you"/chit-chat —
  mostly coherent, occasionally a little blended, since it really is a tiny
  model on a small corpus

The fix for better small talk is the boring, real one: add more example
sentences to the template lists in `brain/dataset_gen.py` and re-run
`brain/train.py`. More phrasing variety directly improves both models.

## Setup

```bash
./run_cranberry.sh
```

This creates `cranberry/.venv`, installs `requirements.txt` into it, and
runs Cranberry. Cariberry.app should already be running (it hosts the
socket), but Cranberry keeps retrying quietly until it is.

### macOS permissions (one-time, done by you in System Settings)

- **Microphone** — needed by this Python process for wake-word listening.
  macOS will prompt the first time `audio/collect_samples.py` or
  `audio/listen.py` opens the mic.
- **Speech Recognition** and **Microphone** for **Cariberry.app itself** —
  already declared in `build.sh`'s Info.plist; macOS prompts the first time
  Cranberry asks it to transcribe something.
- **Accessibility**, for whatever runs this venv's `python3` (Terminal,
  iTerm, etc.) — System Settings → Privacy & Security → Accessibility.
  Required for both the Dock-icon lookup and the real cursor movement/click.
  Without it, `open_app` still works, it just falls back to a plain launch
  instead of the paw-click gesture — run `python -m cranberry.rpa.dock` to
  check.

## Training

```bash
# 1. Wake word — record yourself saying "Hey Cranberry" (and other things,
#    as negatives). Rerun anytime to add more samples.
cranberry/.venv/bin/python -m cranberry.audio.collect_samples

# 2. Train the wake-word CNN on those clips.
cranberry/.venv/bin/python -m cranberry.audio.train_wake_word

# 3. Train the brain (intent classifier + persona generator) on the
#    synthetic corpus in brain/dataset_gen.py.
cranberry/.venv/bin/python -m cranberry.brain.train
```

Cranberry works without step 1/2 (voice activation just stays off — the chat
window still works), and without step 3 (falls back to keyword matching and
canned replies).

## Known rough edges

- **The paw cursor overlay** (`rpa/cursor_overlay.py`) is the most visually
  finicky part: it's an AppKit window driven from a background thread
  outside a full `NSApplication` run loop, nudged to redraw via manual run-loop
  pumps. Cranberry's main thread now runs a real Cocoa event loop (PyObjC's
  `AppHelper`) so it has one to draw into.
  If it doesn't render or looks janky, the click still lands on the right
  pixel regardless — this layer is purely cosmetic.
- **Closing an app** doesn't do a simulated click. Single-clicking a running
  app's Dock icon just refocuses it — actually quitting via click means
  right-click → find "Quit" in the resulting context menu, which is real but
  meaningfully more fragile Accessibility surface. `close_app` instead calls
  `NSRunningApplication.terminate()`, the same underlying action.
- **Dock lookup** (`rpa/dock.py`) only finds apps currently pinned to (or
  running and shown in) the Dock. Anything else falls back to `open -a`.
- Known apps for the intent classifier / templates live in
  `config.KNOWN_APPS` — add yours there (and re-run brain training) if
  Cranberry doesn't recognize an app you use.


## Chat brains (optional)

Pick one in Cariberry's **Settings ▸ Chat brain**. Cariberry sends the choice (and your
API key, which lives in the macOS Keychain, never in a file or this repo) over the
loopback socket. Only your chat messages and a short "who she is" prompt are ever
sent to a provider: never your screen, files or browsing.

| Choice | Needs | Where your chat goes |
|---|---|---|
| On this Mac only (default) | nothing | nowhere. Keyword commands + canned replies, or TinyGPT if you trained it |
| Ollama | Ollama running locally (`ollama serve`) and a pulled model | your own Mac |
| ChatGPT / OpenAI | an OpenAI API key | OpenAI |
| Gemini | a Google AI Studio key | Google |

ChatGPT and Gemini are online services run by other companies: they have their own terms, privacy policies and age limits, and bill you directly for your own key. What they receive is your chat messages plus a short line saying who she is (her name, species, personality, coaching style and the mood you picked). See [PRIVACY.md](../PRIVACY.md).

Replies stream into the drawer word by word. If the chosen brain is unreachable she says
so and answers locally instead. The brain keeps the last dozen turns, so follow-ups work.
You can also run it by hand with `OPENAI_API_KEY` or `GEMINI_API_KEY`
in the environment.

PyTorch is now **optional**: without it commands use keyword matching and small talk uses
canned replies (or your chat brain). Install it only if you want the learned intent
classifier / TinyGPT or the wake-word model.

## Desktop tasks

One sentence can chain steps: "open Notion and start my study playlist", "close Slack,
then open Notes", "start a 25 minute focus and play lofi". (`rpa/chain.py`.) Music starts
Spotify or Apple Music; to play a specific playlist put its URI in
`~/Library/Application Support/DesktopPup/cranberry.json` as `{"playlist_uri": "spotify:playlist:…"}`.
